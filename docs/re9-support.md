# Resident Evil Requiem 支持

| 游戏 | MMTR 版本 | MDF 版本 | 是否完整测试 |
|---|---|---|---|
| Resident Evil Requiem | 251112994 | 2.51（108 字节材质项） | 否 |

[查看全部支持游戏](game-support.md)。

2026-11-26。结论：RE9 的 `.mmtr.251112994` 与 `.mdf2.51` 可以打开、原样另存、编辑 MDF，并新增 UserMaterial 参数与 Texture2D；删除参数或纹理会被覆盖分析拒绝。游戏内效果未验证。

## 一、格式

| 项 | RE9 |
|---|---|
| MMTR 文件头 | per-target：4 组，各组一个 u16 程序数，Shader 区起点在 +0x10 |
| 记录长度 | 0x110 |
| 材质数据标记行 | 无（参数区从第 0 行开始，贴图索引表紧接参数区） |
| MDF 材质项 | 108 字节（flags 后多 8 字节，与鬼武者的 104 字节布局不同） |
| master 根目录 | `MaterialShader/`，部分母版在 `AppSystem/`、`VFX/` 等目录 |

- 标记行：275 个有 MDF 引用的母版（各抽 12 个 PS）在 header=0 下没有越过「参数区 + 贴图/GPBF 索引表」的读取，181 个母版的贴图索引读取从参数区末端开始。8 个母版的 PS 中没有布局标记比较（`icmp` 模板 ID），所以不登记标记行。
- MDF 的游戏仍显示为未知：108 字节布局不能单凭字节区分 RE9、Pragmata 与新版 DD2，游戏身份以 MMTR 资源版本为准。
- 可见性缓冲与 meshlet 路径经 `Instances` 字节 52 读取网格表，形式与鬼武者相同，已按网格表读取排除，不当作材质字段。

## 二、验证

输入：Steam 版解包的 `natives/STM`（455 个 `.mmtr.251112994`，13633 个 `.mdf2.51`）；DXC 为 `dxcompiler.dll` 1.8.2505（Dawn 构建）。

| 检查 | 结果 |
|---|---|
| MMTR 解析与原样重建 | 455 个全部通过，逐字节一致 |
| MDF 解析与原样重建 | 13633 个全部识别为 108 字节材质项，逐字节一致 |
| MDF 字段与母版 UserMaterial 对照 | 母版在语料中的 36095 个材质项：33 592 个参数名、偏移、宽度全部一致；2117 个母版 metadata 没有 UserMaterial（眼球类等）；386 个 MDF 比母版少成员（例：`Env_2Layer_Common_Dirt` 的 `PhysicalMaterialIndex2`），需先同步接口 |
| 新增参数与贴图 | `Env_Default_Emissive` + `ch0100_09_00_00.mdf2.51` 材质 6，一次新增 16 字节参数与一张 Texture2D（记录 7），615 个 Shader 迁移 16 秒完成，导出后重开通过 |
| 迁移前后读取对照 | 615 个 Shader 全部符合预期：参数区读取不变，141 个 Shader 的 548 处贴图索引读取后移 16 字节 |
| 关联布局严格验证 | 原版与编辑后结果相同：422/615 通过，193 个覆盖不足（见第三节） |
| 删除预览 | 拒绝（`eligible: false`） |

可选语料回归：`tests/test_re9_support.py`，设置 `MMTR_TEST_RE9_NATIVES` 指向解包的 `natives` 后执行，缺少时跳过。

## 三、已知限制

- 严格覆盖分析对 193 个 Shader 不完整，所以删除不可用，关联布局验证显示失败。原版文件同样失败，不是编辑引入的问题：
  - 165 个 PS（可见性、实例化阴影、PreTransform）：贴图描述符的使用链流入局部数组，分析遇到 `llvm.lifetime` 后停止。
  - 22 个 meshlet VS/MS/CS：网格表读取没有计入已识别消费者。
  - 6 个 meshlet CS：缓冲读取来源未覆盖。
- 新增依赖迁移本身的严格读取识别；以上只读覆盖缺口不影响新增结果，但「接口验证通过」不能作为 RE9 的整体证明。
- 只做了一组母版的端到端新增；其它母版（例如使用 GPBF 或计算阶段读取贴图的）没有逐个验证。

# 独立仓库迁移记录

2026-10-19，从 `Monkeysama/mmtr-research` 的提交 `0ae9a647fe7c079de5472d859a4a82855016fe80` 复制Workbench v0.3.0源码到本仓库。原仓库保留全部文件和历史，未删除、移动或修改其正在进行的议题、PR和DLL主线。

## 范围与验收

假设：Vue/Tauri、Python编辑核心、解析器及必要构建脚本构成独立依赖闭包。最小实验在新目录运行核心合成测试、MCP真实stdio、前端测试、类型/Vite构建，再构建独立sidecar和桌面程序。通过标准是运行时不依赖旧检出路径、核心版本0.3.0、20个MCP工具及源保护/回滚契约保持。停止于新仓库可开发、构建与提交，不部署游戏或推进DLL研究。

迁移包含界面、Rust宿主、Python核心、只读MMTR解析器、编辑器测试与构建/验证脚本。名称和Shader校验用的MurmurHash3/xxHash64从自有研究脚本提取到 `mmtr_editor/hashes.py`，算法保持；未复制整个研究脚本依赖树。README、使用说明、开发规范与CI按独立产品重写，不沿用原仓库强制关联议题和DLL检查。

未迁移游戏资产、捕获、完整IR、旧output、研究DLL/回放、node_modules、target或预编译核心。目标原有LICENSE保留。已有Pants候选在用户上一轮游戏测试中正常，随后已恢复游戏；那是迁移前证据，不当作本次独立构建的游戏验收。

## 已知限制

- 自动UserMaterial/Texture2D扩展只接受已识别布局，删除接口、Sampler/UAV及新阶段资源表不支持自动迁移。
- 先对材质0新增纹理，再修改材质1旧纹理，既有共享头检查可能误拒绝；这是后续问题，本次迁移不扩大修复范围。
- 真实样本测试仍采用可选本地语料；缺少输入的skip必须单独报告，不能上传游戏资产满足CI。
- 不保证任意HLSL重建覆盖或跨游戏格式兼容，不从静态验证推断视觉等价。

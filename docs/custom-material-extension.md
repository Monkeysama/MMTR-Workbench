# 自定义材质接口扩展与地址核对

材质布局扩展会改变参数区后的纹理与 GPBF 索引位置。新增字段没有 Shader 消费者，并不意味着旧 Shader 可以保持原始寻址：参数区扩容需要迁移全部既有资源读取，纹理数量增加还会移动后面的 GPBF 索引。

## 已支持的读取

自动迁移支持来源可证明的 32768B heap 材质 CB、BindlessBuffer 和 UserMaterialInstances 读取。材质 CB 的 `cbufferLoadLegacy.i32` 与 `cbufferLoadLegacy.f32` 按相同的字节位置识别，但保留各自的数据类型。未知读取、aggregate 消费或无法对应原字段的尾部地址仍然拒绝。

原生动态纹理追加保留已有资源声明和 MMTR 绑定，依据 MDF 纹理顺序证明实际索引。支持无界 `bindlessTexture2D` 的旧式／现代句柄和已注解的资源堆 Texture2D，索引限直接读取或加零。不同 PS 可分别沿用固定与动态策略，同一 PS 混用、跨阶段共享或未知索引运算会回滚。新增槽仍需作者另行编写采样逻辑。

新版材质尾部还可能含布局标记：已验证编码为 `标量数 | (纹理数 << 10) | (GPBF数 << 18)`，位置为参数及资源尾部之后向上对齐 16 字节。仅在实际 MDF 计数、读取地址和唯一 `icmp eq/ne` 消费者一致时更新地址／常量，保留原有检查。不能用 MMTR 成员数替代 MDF 标量数，也不能把未知越界读取当作标记。

删除接口同样核对标记。即使参数块因 padding 保持原大小，删除属性仍会减少实际分量数；紧凑重排或删除纹理还可能改变标记地址。删除计划包含新旧 MDF 分量数，编译后重新证明地址、比较值与消费者；未知尾部、额外使用者或旧计数仍拒绝。相同整数出现在其它表达式中不会被批量替换。

自定义 fresnel 等效果可直接使用浮点 CB 读取。曾经仅识别整数读取的实现会在新增接口时报“未知材质读取”，事务回滚，不会生成有效的新接口。不能通过忽略该读取或换回未迁移的旧 Shader 来绕过检查。

## Stocking 的本地案例

2026-10-20 核对用户提供的 `MKCustomStocking.mmtr.240906211` 与 MDF `ch03_060_0002.mdf2.45`，目标材质为 Stocking。源 MMTR SHA256 前缀为 `c69a93c247e3b5b9`，参数区为 1024B，含 21 个纹理及 4 个 GPBF；PS274 包含 5 处自定义浮点材质读取。

历史 `matcap2` MMTR（SHA256 前缀 `701d8f8213022bd9`）参数区扩到 1168B，但 PS274 中作为 LocalPosMap 索引的 `%688` 仍从 944B 读取，并传入 `createHandleFromHeap`。944B 实际对应 Fresnel_Intensity；历史 MDF 的值为 0.266，按索引解释得到 `0x3e883127`。该构建存在可直接核对的地址错误，但静态分析不能确认全部游戏崩溃都只由这一点引起。

全文件核对发现，历史候选 PS274 的 21 个纹理与 4 个 GPBF 读取均不符合目标布局；其它 710 个 Shader 的原取值地址符合预期。部分尾部读取虽有迁移痕迹，仍不代表正确。原有迁移代码对本就位于参数区内的旧地址不会推断出纹理身份，因此不能自动修复任意外部补丁造成的错位。扩容必须从已确认布局正确的源版本开始；替换 Shader 时必须使用同一布局生成的版本。

探测代码没有新增采样，不代表整个 Shader 没有既有采样或 heap 句柄创建。读取指令遗留在 IR 中但没有取值消费者，也不能以其寄存器范围判断实际访问；应跟踪有效 `extractvalue` 的字段身份及其后续使用。

## 验证边界

回归测试覆盖浮点/整数类型保持、原参数不动、纹理与 GPBF 边界、连续 3 个纹理与 9 个参数扩展，以及未知消费者和尾部越界拒绝。真实文件另经 MCP 导出、重开和字段核对；这些属于 CPU 静态证据。

2026-10-29 增加删除标记与显式关联验证回归：覆盖参数块大小不变的分量减少、标记地址收缩、纹理数量变化、编译后 guard 核对及失败回滚。显式关联验证可检查重新打开且没有 metadata 修改的文件；默认 metadata 检查此时仅返回 skipped，不代表完整布局通过。

当前 Skin 对的只读验证覆盖 643 个 Shader、2395 条记录和 4 个关联材质，464 个 Shader 在已支持范围通过，179 个因其它未知访问失败，成功证明 302 处标记；整体报告为 failed。输入 MMTR SHA256 为 `262872b0166a17b48ec028c0a158710368de875052b6cc93af883e2c0a697bff`，MDF SHA256 为 `04f9f18ba6451e2bc7b923f547bff3f479e0d12d2b54043c5322218a524e010e`，验证前后字节一致。此结果没有放开未知访问，也没有重新进行游戏验收。

游戏测试先只新增一个使用 NullBlack 的空纹理槽，不插入采样或着色补丁，保留原参数区大小和原效果。只有游戏反馈才能确认该候选在真实渲染环境中的结果；DXC 验证通过不能代替 GPU 或游戏验证。
